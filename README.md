# Reaction world models trained on reported successes fail silently: data and code

High-throughput experimentation data and analysis code for the study of reaction models trained on success-only records and scored on measured experiments that were not run (Lin Tan, Yaxian Kong, Chonghuan Zhang and Kuangbiao Liao).

## Contents

| Folder | Contents |
|---|---|
| `data/raw/` | 19 reaction tables and the condition dictionary from which every analysed record is built |
| `data/EXCLUDE_wells.csv` | 396 acylation measurement identifiers excluded from all analyses because their records conflict between data versions |
| `code/` | Analysis and figure scripts, run in the order below |
| `out/` | Outputs of the scripts, so that every step can be checked without rerunning the model runs |
| `figures/` | Figures 2–5 and Extended Data 2 as generated by `code/13_figures.py` |

Figure 1 is the manuscript concept overview. Its twelve illustrative well-grid rows and numerical findings use the result tables included here. Its editable layout and the native ChemDraw example in Extended Data 1 are maintained in the manuscript project, outside this analysis package. The concept renderer also imports manuscript citation and drawing helpers, which are not part of this analysis package.

## Data

Each raw table has one row per well. The scripts use the substrate and product SMILES (`sub_1_smiles`, `sub_2_smiles`, `product_smiles`), the condition (`condition_id` and the reagent, solvent, temperature and time identifiers, resolved through `0_total condition_*.xlsx`), the measurement (`yield`, `yield_clf`), the measurement identifier `name0` and the plate archive.

Every record follows one convention:

| Record | Analysed value |
|---|---|
| Numerical yield | That yield, as a fraction from 0 to 1 |
| Blank yield, `yield_clf` = 0 (screen found no product) | 0 |
| Blank yield, `yield_clf` = 1 (product detected, not quantified) | Missing |
| Blank yield, no `yield_clf` | Missing |

Missing records are never imputed.

`code/01_build_blocks.py` builds one complete substrate-pair × condition block per reaction array and writes `out/wells.csv.gz` (154,377 analysed records, 19 arrays, 2,248 substrate pairs). Seventeen arrays enter the analysis; the Minisci and Suzuki Bpin blocks have fewer than 30 substrate pairs or 24 conditions. Pairs measured twice under the same condition are written to `out/replicates.csv` and serve only as a repeatability reference. `out/conditions.csv` lists the reagents, solvent, temperature and time of every block condition.

## Reproduce

Use Python 3.13.3 and install the pinned dependencies in a fresh virtual environment. From this folder:

The neural-network check uses PyTorch; a CPU build is sufficient. `requirements.txt` enables the official PyTorch CPU wheel index and pins the tested package version.

```text
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cd code
../.venv/Scripts/python 01_build_blocks.py
```

On macOS or Linux, use `.venv/bin/python`. Run the scripts from `code/` in this order; each writes to `../out/` or `../figures/`:

| Step | Script | Writes |
|---|---|---|
| 1 | `01_build_blocks.py` | `wells.csv.gz`, `conditions.csv`, `replicates.csv`, `blocks_summary.csv` |
| 2 | `03_synthetic_check.py` | Checks the policies, models and intervals on planted data; writes nothing |
| 3 | `04_run_pilot.py`, then `04_run_pilot.py --extension` | `pilot_*.csv`: the three main arrays, then the other fourteen |
| 4 | `05_literature_decomposition.py` | `literature_decomposition.csv` |
| 5 | `07_book_score.py`, then `07_book_score.py` with the fourteen further array names as arguments | `book_score.csv` |
| 6 | `09_example_and_chemistry.py`, then `28_chemistry_gap.py` | `example_pair.csv`, `chemistry_readout.csv`, `chemistry_rows.csv.gz`; `chemistry_gap.csv` (Extended Data 2b) |
| 7 | `12_fig2a_wells.py` | `fig2a_wells.csv.gz` |
| 8 | `15_validation.py` | `validation_*.csv` |
| 9 | `16_literature_overlap.py`, `17_literature_check.py`, `18_literature_pool.py`, `19_literature_model.py`, `24_literature_curve.py` | Literature comparison, literature-trained models and their training-size curve (see below) |
| 10 | `20_external.py` | `external_*.csv` (see below) |
| 11 | `21_gbm.py`, then `31_mlp.py` | `gbm_*.csv`; `mlp_errors.csv.gz`, `mlp_summary.csv`, `mlp_book.csv`, `mlp_verdict.csv` |
| 12 | `29_silent_pairs.py` | `silent_pairs.csv`, `silent_pairs_example.csv` (pairs that leave no literature-style record; Figure 3 and Supplementary Table S5) |
| 13 | `32_dead_pairs.py` | `dead_pairs_splits.csv.gz`, `dead_pairs_summary.csv`, `dead_pairs_verdict.csv`: new-pair viability rankings and false-go rates (RF and MLP; requires PyTorch) |
| 14 | `22_si_tables.py` | `out/si/`: the Supplementary Tables |
| 15 | `13_figures.py` | `figures/Figure2–5.pdf/.png`; `figures/ExtendedData2.pdf/.png` when per-pair literature inputs are available |

Random draws use fixed seeds. The model runs in steps 3, 5, 8, 11 and 13 can take hours on a desktop computer. In step 13, test-pair yields do not enter model training targets, but supply the condition means that steer attempts on training pairs. Dead pairs have no measured library condition reaching 20%; this definition makes no claim about unmeasured conditions. The supplied split-level metrics support the reported aggregation; per-pair predictions were not saved.

**Literature records (step 9).** The literature records used here were extracted manually from the original publications and checked against a commercial reaction database; the records are not included. Step 9 reads the literature records from CSV files in `WM_LIT_DIR`: 97 CSV files named `lit_hq_y_sx_pt_part_*.csv` in the folder given by `WM_LIT_DIR`, one row per reaction record, with the columns `substrates` and `products` (SMILES separated by "." or ";"), `reagent_txt_solvent_exclusive`, `reagents_smiles`, `solvent_txt`, `temperature_celsius_raw`, `time_hrs_raw`, `number_of_steps`, `number_of_stages`, `yield_reg` (yield as a fraction), `record_id`, `reaction_id`, `source_type`, `source_raw`, `journal`, `year` and `patent_number`. Aggregate outputs are included in `out/`. The per-pair literature comparison (`literature_check_pairs.csv`) contains literature yields and is not included; regenerating Extended Data 2 and the corresponding Supplementary Table therefore requires step 9. Without it, `13_figures.py` still draws all four evidence figures (Figures 2–5), and `22_si_tables.py` preserves the shipped literature-comparison table in `out/si/`.

**External arrays (step 10).** `20_external.py` reads two published datasets, which are not redistributed here: `Dreher_and_Doyle_input_data.xlsx` (Ahneman et al., Science 360, 186–190, 2018) and `aap9112_Data_File_S1.xlsx` (Perera et al., Science 359, 429–434, 2018, Data File S1). Place them in `data/external/` or set `WM_EXTERNAL_DIR`.

Input locations can be changed with `WM_RAW_DIR` and `WM_EXCLUDE`.
